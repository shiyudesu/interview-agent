# 模拟面试 Agent 业务范围

## 1. MVP 配置

- MVP 仅提供 `Go 后端` 面试方向。
- 面试难度固定为中级，不提供难度选择。
- 面试语言仅支持简体中文，技术名词保留英文。
- 用户可选择 `5`、`10` 或 `15` 道主问题。
- 用户不能自定义技术栈、知识领域或题目。

Go 后端包含以下知识领域：

1. Go 语言与标准库。
2. 并发、运行时与性能。
3. HTTP、RPC 与 API。
4. 数据库与存储。
5. 缓存、消息队列与分布式基础。
6. 测试、可观测性与工程实践。

题量对应的覆盖规则：

- 5 题：覆盖 5 个不同领域，未覆盖领域在报告中标记为“未评估”。
- 10 题：覆盖全部 6 个领域，并提高 Go、并发相关领域的题目占比。
- 15 题：覆盖全部 6 个领域，每个领域至少 2 题。

MVP 不包含代码阅读、代码编写、伪代码或在线编程题。

## 2. 账户与历史

- 支持 GitHub 登录和邮箱验证码登录。
- 不根据相同邮箱自动合并账户。
- 用户登录后可以主动绑定另一种登录方式。
- 用户可以主动绑定邮箱不同的 GitHub 账户；绑定不会改变账户主邮箱。
- 账户只保存登录身份、邮箱和显示名称。
- 每个账户同时只能有一场进行中的面试。
- 存在进行中面试时，用户必须选择继续该面试，或确认放弃后创建新面试。
- 历史记录按时间展示，不提供跨场比较、趋势、排名或成长分析。
- 用户可以删除单场历史记录。
- 用户可以删除账户及其全部数据。
- 删除确认后，相关数据立即不可访问且不能恢复。
- 相关内容在 7 天内完成物理清除。
- 物理清除后仅保留不可还原的删除时间、数据类别和执行结果，不保留邮箱、问题、回答、评分或报告。

## 3. 题库规则

- 首发题库至少包含 90 道审核通过的主问题，每个知识领域至少 15 道。
- 每道题必须包含：
  - 审核后的主问题。
  - 所属知识领域。
  - 带权评分点。
  - 可追问目标。
  - 知识说明。
- 主问题必须来自审核题库，不允许模型自由生成。
- 模型只允许调整语序、称谓和上下文衔接。
- 改写不得增删条件，或改变技术术语、考察目标、难度和评分点。
- 系统需要保留题库原文和实际展示文本。
- 追问目标由题库预先定义，模型只能围绕目标组织具体措辞。
- 选题时优先避开用户最近 3 场面试中出现过的主问题。
- 题库不足时允许重复使用历史题目。
- 面试和报告均不向用户展示内部题库来源。
- MVP 不提供题库管理界面。

## 4. 面试流程

### 4.1 开始面试

- 用户选择题量后开始面试。
- 开始时确定整场面试的知识领域和主问题蓝图。
- 用户后续回答不会改变剩余主问题。
- 面试中仅显示当前题号和总题量。
- 面试中不显示知识领域、实时分数或剩余追问次数。

### 4.2 回答

- 系统每次只展示一道主问题。
- 用户提交回答后不能编辑。
- 在进入下一道主问题前，用户可以主动补充当前回答。
- 空内容不能提交。
- 用户可以明确表示“不知道”或主动跳过问题。
- 用户可以请求澄清题意。
- 澄清只能调整问题表达或说明边界，不得提示答案。
- 用户请求澄清不占用系统追问次数，也不影响评分。

### 4.3 系统追问

- 每道主问题最多追问 2 次。
- 回答含糊、不完整或需要验证理解深度时可以追问。
- 最多进行一次澄清性追问和一次深度追问。
- 回答已经充分命中评分点时直接进入下一题。
- 用户明确表示“不知道”或主动跳过时不再追问。
- 用户回答完全无关时，系统允许澄清一次；澄清后仍无关则进入下一题。

### 4.4 暂停与恢复

- 关闭页面、退出登录或离开面试页不会结束面试。
- 进行中的面试可以跨设备恢复。
- 提交回答、请求澄清、补充回答和跳过问题属于有效活动。
- 最后一次有效活动后超过 24 小时，面试自动变为放弃状态。

## 5. 面试终态

| 终态 | 触发条件 | 报告 |
|---|---|---|
| 正常完成 | 处理完用户选择的全部主问题 | 生成完整报告、总分和领域分 |
| 提前结束 | 用户选择“结束并生成报告” | 生成不完整报告，不提供总分 |
| 主动放弃 | 用户选择“放弃面试” | 不生成报告 |
| 超时放弃 | 最后一次有效活动超过 24 小时 | 不生成报告 |

- 正常完成后始终生成完整报告，即使所有问题均为 0 分。
- 终态面试不能恢复作答。
- 报告生成后，本场面试变为只读状态。

## 6. 评分规则

- 每道主问题根据题库中的带权评分点得到 `0–100` 分。
- 主回答、主动补充和追问回答合并后进行评分。
- 发生追问本身不扣分。
- 每道主问题等权。
- 总分为本场全部主问题分数的平均值。
- 领域分为该领域全部已选主问题分数的平均值。
- 总分和领域分取整数。
- 5 题模式下未覆盖的领域不计为 0 分，而是标记为“未评估”。
- 报告不提供通过/不通过结论，也不显示优秀、合格或中级达标等固定标签。

以下情况均按该题 `0` 分计入正常完成面试的总分：

- 用户主动跳过。
- 用户明确表示“不知道”。
- 澄清后回答仍完全无关。
- 回答相关但没有命中任何评分点。

这些情况分数相同，但在报告中使用不同的原因标签。

## 7. 报告

### 7.1 完整报告

正常完成面试后生成，包含：

- 总分。
- 各已评估知识领域的分数。
- 整体表现说明。
- 掌握较好的知识点。
- 回答错误、不完整或遗漏的知识点。
- 建议优先提升的内容。
- 后续学习和练习建议。
- 逐题反馈。

### 7.2 不完整报告

用户提前结束时生成，包含：

- “评估不完整”标记。
- 已完成题目的逐题结果。
- 已有回答所反映的知识点反馈。
- 后续学习建议。

不完整报告不提供总分。

### 7.3 逐题反馈

每道题展示：

- 实际展示的问题。
- 用户回答摘要。
- 题目分数。
- 命中的评分点。
- 缺失或错误的关键点。
- 评分依据和扣分原因。
- 针对性的改进建议。

0 分题仍必须提供反馈：

- 不知道或跳过：说明考察目标、缺失知识点和学习方向。
- 答非所问：说明问题要求与回答内容为何没有对齐。
- 完全错误：指出错误概念并给出正确的学习方向。

报告可以列出关键知识点，但不提供可直接背诵的完整标准答案。

### 7.4 报告约束

- 报告必须基于本场实际问题、回答和评分点。
- 报告生成后固定保存，不自动重新计算。
- 不提供重新生成、评分申诉或修改评分功能。
- 报告生成后不能继续与面试官对话。
- MVP 仅支持站内查看，不支持 PDF、下载或公开分享。
- 报告仅用于面试练习，不代表正式招聘结果。

## 8. 历史记录

历史列表展示：

- 面试日期。
- 面试方向。
- 题量。
- 面试状态。
- 总分，仅正常完成时展示。

历史详情按状态展示：

- 正常完成：完整问答记录和完整报告。
- 提前结束：完整问答记录和不完整报告。
- 主动放弃或超时放弃：已有问答记录和放弃状态，不提供报告。

## 9. 不在 MVP 范围

- 其他技术方向和自定义技术栈。
- 用户选择难度或知识领域。
- 语音、视频和虚拟面试官。
- 代码题、在线编程、代码运行和自动判题。
- 简历或岗位描述分析。
- 特定企业面试模拟。
- 行为面试、算法面试、真人面试和多人面试。
- 题库管理后台。
- 报告导出和分享。
- 跨场趋势、能力排名和成长分析。
- 多语言面试。
- 付费、订阅和社区功能。
